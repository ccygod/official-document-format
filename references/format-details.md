# 公文格式skill（official document skill）

Create a document from this template. Keep the reference file unchanged.

## Default document structure

- **正文从模板“标题2”开始，不使用预设“标题1”。** Main document `Title` remains separate. Map the source's top content heading to template heading 2, its children to heading 3, then heading 4/5 as needed. Preserve relative hierarchy; do not flatten all headings. The top content heading uses regular 黑体 and left alignment. Resolve effective style names/roles rather than fixed IDs. If the source already begins at heading 2, do not shift it again on later runs.
- **默认不带目录。** Remove template and source TOCs, including manual entries, `TOC` fields, cached results and TOC content controls. Do not generate a new TOC. Preserve actual sections and headings that merely mention “目录”.
- **默认无项目符号圆点。** Convert bullet lists to normal body paragraphs with the requested typography and first-line indentation. Inspect direct `w:numPr` and the full paragraph-style inheritance chain; resolve `numId → abstractNum → lvl/numFmt` and level overrides. Use explicit `w:numId w:val="0"` to suppress inherited numbering. Remove only leading literal markers such as `•`、`·`、`▪`, including markers split across runs; retain meaningful internal dots and deliberate numbered steps. Deleting a visible character alone does not remove automatic bullets.

`scripts/apply_official_rules.py` applies these defaults; `scripts/check_official_document.py` rejects violations. Explicit user requests may override a default: pass the matching `--heading-start 1`, `--keep-toc`, or `--keep-bullets` to both writer and checker only for that request. Keep the reference asset unchanged; its sample heading-1/TOC/list content is not an output requirement.

## Workflow

1. Read `artifact-template.json` and resolve its paths relative to this skill directory.
2. Read [semantic roles and acceptance](references/semantic-roles.md), classify the content, and save `roles.json` before formatting. Load [@documents](plugin://documents@openai-primary-runtime) and invoke its reference/template workflow with the retained file.
3. Treat the user's prompt and available sources as the content input. Do not invent facts merely to fill a template slot.
4. Clone or import the reference instead of replacing its visual system with generic defaults.
5. Run `scripts/check_official_document.py` with the resolved body size (for example, `--expected-half-points 28` for 四号), the requested line multiple (`--expected-line-multiple 1.35`), paragraph-before lines (`--expected-before-lines 0`) and paragraph-after lines (`--expected-after-lines 25`), table-follow spacing (`--expected-table-after-lines 50`), together with `--require-snap-to-grid-off`; when全文启用分页控制时 also pass `--require-full-pagination-controls`. Render with WPS `word2photo` for the primary visual check, and use the generic renderer as secondary diagnostics before returning the final artifact.

## Fidelity

Preserve page setup, sections, styles, ordered lists, tables, headers, footers, and recurring page elements, subject to the default structure rules above. 正文和内容标题（标题1–5）默认均首行缩进2字符；居中的主Title、表题、图注及表格短字段保持各自对齐。用段落显式属性实现，不用空格或Tab模拟。用户明确要求标题顶格时，writer传`--heading-indent-chars 0`，checker传`--expected-heading-indent-chars 0`。 Inline level-5 labels such as `时间安排：` and `阶段性成果：` must split their suffix into normal body formatting when prose remains on the same line. Use exactly one numbering authority per paragraph: preserve a source-text marker only when `w:numPr` is absent; when `w:numPr` is present, remove the matching leading literal marker before writing. Numbering inherited from a paragraph style counts as `w:numPr` too. Before changing typography, resolve the requested body size; if it is not stated, ask first. Apply the requested size to body and heading 1–5 roles while preserving the main Title size, and scale real images by the size ratio only when they exist. Numbering-level run properties in `word/numbering.xml` must be resized with the heading text. Do not rely on the reference numbering definitions or inherited defaults: write explicit `w:rFonts`, `w:sz`, and `w:szCs` for every numbering level used by heading 1–5, using the effective font family of the corresponding heading and the resolved body size. A document passes this check only when the visible numbering symbol and the heading text render at the same size. Remove title-block-only page breaks, and plan explicit semantic title line breaks that preserve institution names and produce a balanced trapezoid/diamond-like shape. Level-2 headings use regular 黑体 without bold. Keep one blank Normal-style paragraph only between the top title block and the body; do not add blank lines after hierarchy headings.

For pagination controls, treat the three Word/WPS paragraph settings as explicit OOXML properties rather than visual assumptions: `w:widowControl` (孤行控制), `w:keepNext` (与下段同页), and `w:keepLines` (段中不分页). When the user requests全文启用, write all three properties to every document paragraph, including paragraphs inside table cells, and add `w:cantSplit` to every table row. When the user has not requested全文启用, apply `w:widowControl` and `w:keepLines` to body and heading paragraphs, and apply `w:keepNext` to headings, captions, table titles, and image paragraphs. Check the effective XML after style inheritance is resolved; a style default that is not present on the paragraph or its effective style does not count as enabled. Render every page after applying these controls because `w:keepNext` can change pagination materially.

For document-grid and line-spacing settings, explicitly write `w:snapToGrid w:val="0"` to every main-document paragraph and paragraph style so “如果定义了文档网格，则与网格对齐” is visibly off in Word/WPS. Use 1.35-line spacing as the default official-document baseline unless the user gives another value: set `w:spacing w:line="324" w:lineRule="auto" w:before="0" w:beforeLines="0" w:after="0" w:afterLines="25"` on every main-document paragraph and every paragraph style, including table and image paragraphs. This means段前为0、段后为0.25倍行间距. For every table, write an additional `w:beforeLines="50"` on the first paragraph immediately following the table, creating visual separation without inserting an empty paragraph. Preserve header, footer, footnote and endnote parts by default because they may contain WPS fields and page-number fallbacks; touch those parts only when the user explicitly requests it. Do not leave these settings to template inheritance; verify them in the saved package and with WPS rendering.

**HARD GATE — EXPLICIT BODY SIZE REQUIRED.** Before editing, the user must provide the target body size in a concrete form such as `小四（12磅）`, `四号（14磅）`, or an equivalent numeric point value. If the request omits it, stop before any formatting mutation and ask for it. Do not infer it from the reference document, the source file, the operating system, WPS defaults, or a phrase such as“按原文”“按模板”“保持原样”; those are not size confirmations. A title-size instruction alone does not satisfy this gate. After the user supplies the body size, apply it to body text, heading levels 1–5, their numbering symbols, and any proportional image scaling; keep the main Title size separate unless the user also specifies it.

For inserted tables and images, preserve the semantic styles as well as the visible appearance: add a separate centered table-title paragraph immediately before each table, using the reference convention `表1  ……`, `表2  ……` and sequential numbering; every paragraph inside a table cell must carry the effective `表格` or `表格正文` paragraph style (do not rely on `Table Grid` or inherited `Normal`), the first row must be a repeating `w:tblHeader` row with `w:cantSplit`, and table cells must use explicit black borders, black text, and a plain white fill. Remove cell shading or set every `w:shd` fill explicitly to `FFFFFF`; do not use blue, gray, or theme-color table fills. Compute each column's minimum from its longest unbreakable cell plus cell margins, keep index/序号 columns narrow, and give the remaining width to long description columns; never split the available width evenly by default. The paragraph containing an inline drawing and its separate caption must carry the effective `图片` paragraph style; the caption is centered and uses the `图1  ……` convention. A visual table that merely looks correct while its cell paragraphs remain `正文` is a failed result.

Table titles (`表1  ……`) and figure captions (`图1  ……`) use the same `图片` paragraph style, regular weight, centered alignment, and identical font family, font size and color. A table title is outside the table; it must not use the cell styles `表格`/`表格正文` or heading formatting. `scripts/caption_format.py` resolves the first existing figure caption's effective run typography, including style inheritance and direct overrides, and applies that profile to every table title and figure caption. If there is no figure caption, resolve the named `图片` style as the fallback. Explicitly disable `w:b` and `w:bCs`, remove stale direct run font/size overrides by replacing them with the resolved caption profile, and keep the table title with its table. `apply_official_rules.py` performs this pass automatically; `check_official_document.py` must reject differing caption fonts, sizes or weights. Never hardcode a style ID or a separate bold 黑体 table-title format.

In Chinese prose, remove spaces at Chinese–English boundaries (`WPS中`, `Word表格`, `公文格式Skill`); preserve spaces that belong inside an English phrase such as `New York`.

Do not invent a subtitle, sample label, or annotation to fill the title block. Keep a source-provided subtitle only when the source clearly marks it as such; render it centered and in parentheses when that is the source convention. If no subtitle exists, leave it out.

For repeatable width decisions, run `scripts/smart_table_widths.py input.docx --json` on a copy before applying changes. The report classifies columns as `narrow`, `regular`, or `flex`, calculates page-available width from the section margins, protects minimum readable widths, and allocates leftover width to long-text columns. The table itself must carry table-level `w:tblPr/w:jc w:val="center"` unless a formal template explicitly overrides the alignment. Use `--apply` only after reviewing the report, then render in WPS. Tables with merged/grid-span cells are reported for manual review rather than being blindly rewritten.

The same semantic pass must also set short-field columns such as序号、状态、日期 to centered alignment, long-text columns such as主要内容、说明、依据 to left alignment, repeat the first row on later pages, prevent row splitting, keep each `表n` title with its table, and keep each image with its `图n` caption. Use `表格` for short values, names, dates, statuses, and compact enumerations, with centered alignment. Use `表格正文` when a cell contains sentence punctuation (`，`、`。`、`；`、`：`) and is long enough to wrap, or when a description is a long enumeration of at least 20 Chinese characters containing `、`; apply first-line indentation, left/justified prose alignment, and the same table font and line spacing. Do not apply `表格正文` to serial numbers, dates, statuses, short labels, or compact one-line values. The checker and writer must use the same predicate so a cell cannot pass visually while carrying the wrong semantic style. Widths are accepted only after the rendered table is checked for wrapping, clipped text, oversized blank columns, and page-break damage.

User instructions control requested content and explicit deviations. The retained reference controls layout and formatting where the user has not requested a change.

## v2 stability contract

Before editing, inspect effective styles and numbering rather than trusting fixed style IDs. Read the complete content and create a reviewed semantic role map as described below. Produce a change plan with user overrides and expected changed parts. Apply deterministic rules with `scripts/apply_official_rules.py <input> <output> --role-map <roles.json> --body-half-points <resolved-half-points> --line-multiple 1.35 --before-lines 0 --after-lines 25 --table-after-lines 50` (add `--full-pagination-controls` when requested), then run `scripts/check_official_document.py <output> --role-map <roles.json> --expected-half-points <resolved-half-points> --expected-line-multiple 1.35 --expected-before-lines 0 --expected-after-lines 25 --expected-table-after-lines 50 --require-snap-to-grid-off` (plus `--require-full-pagination-controls` when requested), `scripts/check_package_preservation.py`, and `scripts/check_idempotence.py`; finish with WPS `word2photo` page-by-page inspection. A second run must not add another marker, blank paragraph, title line break, or formatting mutation. For inserted tables, require explicit borders and cell geometry; for inserted images, verify the relationship and WPS-rendered extent. Run `python -m unittest discover -s scripts -p 'test_*.py' -v` after changing the structure writer or checker. The acceptance audit must first reject heading-1 body paragraphs, TOC remnants, and direct/inherited/literal bullets unless explicitly requested; it must also include numbering-level font/size parity with heading text, line-spacing parity, explicit before/after spacing, table-follow spacing, explicit snap-to-grid-off, presence of the requested pagination properties on the requested paragraph scope, repeating table headers, and `w:cantSplit` on every table row.


## Semantic decisions before formatting

The agent must read the whole document and infer the outline from meaning, adjacent paragraphs, parallel sections and parent/child relationships. Existing style names, bold text, numbering and font size are evidence, not the semantic decision. Identify headings even when the source marks them Normal; do not promote every short label or numbered step. Distinguish a standalone section heading from a field with an inline value and from narrative text. For a meeting agenda, standalone “会议主题”“会议时间与地点”“参会人员”“会议议程” normally organize top-level sections and map to heading 2; each agenda item inside the agenda section maps to heading 3. This is an example of reasoning from document structure, not a keyword whitelist.

Save the reviewed final roles in `roles.json` with `complete: true` (every substantive direct-body paragraph must be covered); pass that same file to both writer and checker. The map is an auditable result of the agent's semantic reading, not a claim that a regex script understands the document. The writer resolves actual style IDs from role names, applies the map after source-hierarchy normalization, and materializes the requested paragraph indentation. The checker must reject any planned heading left as body, wrong hierarchy, missing or ambiguous locator, and absent or incorrect 2-character indentation. Check style association, outline level, numbering, direct overrides and rendered appearance separately; a font change alone is not a heading conversion.

For semantic headings, use the target template role's numbering form by default: heading 2 uses 一、 and heading 3 uses （一）. A source heading's literal 一、 is not a reason to keep the same marker at both levels. Remove only the original heading marker from the working text before applying the reviewed map, record `"numbering": "template"` on heading entries, and let the inherited template list supply it. Preserve deliberate body-list/step numbers and identifiers. Do not disable all template numbering with `numId=0` as a convenience. Explicit requests to retain unnumbered headings or source marker forms take precedence. Do not describe a document as having “no heading style” when OOXML already associates the paragraph with one; report the observed style and the actual unresolved UI discrepancy.

A checker failure blocks the completion claim. Diagnose and repair the checker if it is wrong, then rerun it; do not silently return an older file or skip the failing assertion. Numeric zero indentation is zero, not an error because the string `"0"` is truthy. After any final file replacement, recheck the exact file delivered. Structural pass, semantic-plan pass, WPS visual pass and UI-property confirmation are distinct evidence; report only checks actually performed.

The named paragraph style definition and applied paragraph must agree on requested indentation. Update both; do not hide stale style settings behind direct formatting. Validate style properties as well as paragraph properties and numbering-level typography.
