### 本轮证据

- 自动化测试：44项，覆盖既有结构规则、有效文字字体与字号、主题字体冲突、分页属性显式关闭、短字段列宽、长时间安排列、正文强调和无关列表保留、统一入口失败不交付、复杂结构分流、图像字节保留及重复处理。
- 独立前向测试：由未参与实现的评估者从一份新建的“城市公共数据质量抽检实施说明”原文决定角色。14个正文段落、一个三列表格；日期、解释性标签和两条步骤保留为正文。初测确实发现标题空行、表题边框、主题字体残留问题，修复后重新测试通过。该材料之后进入公开回归样例，不再作为未来版本的未见测试集。
- 本地历史材料执行回归：四组材料，覆盖会议议程、招生咨询方案、校企共建图表方案、技术方案对照报告；执行结构检查、内容对账、包保留和重复处理。已有材料角色清单不是独立盲测结果。
- 本机WPS视觉检查：陌生合成样例1页、含真实图片与表格的历史回归9页。发现并修复“时间安排”长内容被误设为窄列、源正文keepNext链引起标题块断页、表题与表格分离。客户文本、图片、来源及日志不进入公开仓库。
- GitHub Actions继续在Python 3.10和3.12运行自动化测试。云端CI不运行WPS，不能用CI通过代替WPS视觉验收。

### 已知限制

- 只有一个独立新材料案例，不代表所有新文档全自动正确。模型给出的角色清单仍需要对照原文独立复核。
- 内容控件、文本框、修订、多节混排及合并单元格由统一入口预检分流，不删除结构强行继续。
- 列宽为有明确边界的启发式，不能保证最优排版；表格字号沿母版表格角色，正文大小不会偷偷改成表格大小。
- 仅格式化入口不擅删目录、圆点或文字编号。需要按默认规则清理时先制作副本、记录允许变化，再重新核对角色清单和内容。主标题语义换行也属于模型准备步骤。
- 全文keepNext会产生大段链式分页。用户明确要求全文启用时写入，但仍须逐页检查；默认模式仅标题、表题和图片等需连带的角色启用。
- 原母版、旧展示图记录的是来源/历史示范；当前默认和用户覆盖由config/official.json与处理报告确定。

## 复现

```sh
python -m pip install -r requirements.txt
python -m unittest discover -s scripts -p 'test_*.py' -v
python scripts/pipeline.py inspect examples/forward-case/input.docx --out inventory.json
python scripts/pipeline.py format examples/forward-case/input.docx output.docx --format-profile official_cn --role-map examples/forward-case/roles.json --body-half-points 24 --numbering-mode automatic --report audit.json
```

`roles.json`包含用户/模型明确给出的表题，入口不会凭空编写。测试样例和图示为原创虚构内容。
