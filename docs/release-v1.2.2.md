# v1.2.2 表格居中与自动序号模式

本次修订针对两个实际验收遗漏：表格标题和单元格文字虽然居中，表格本体仍然可能贴在页面左侧；统一入口虽然使用了带编号定义的母版样式，但没有在开工前要求用户明确是否启用自动序号。

## 修订内容

- 表格本体默认写入`w:tblPr/w:jc w:val="center"`，检查器会拒绝没有表格级居中的成品；WPS渲染回归确认窄表格移动到页面中央。
- `pipeline.py format`现在必须提供`--numbering-mode automatic|manual`。
- `automatic`模式使用母版中带编号定义的标题预设样式，段落层级调整后由Word/WPS重新计算编号。
- `manual`模式移除标题样式和段落的有效自动编号，原文已有的中文或阿拉伯数字编号保留为普通文字，不自动补写。
- 自动模式遇到原文已有“一、”“（一）”等文字编号时，会在工作副本中去掉重复标记，再由模板编号负责显示；内容对账会把这一项作为明确允许的编号归一化记录。
- 报告新增`numbering_mode`字段，避免成品无法追溯当时采用了哪种编号策略。

## 验证

- Python单元测试：54项通过。
- 全矩阵：五种格式包 × 两种编号模式 × 五类材料，共50/50结构执行通过；正文14磅五格式矩阵通过。
- 自动编号矩阵：标题段落可解析出有效`numId/ilvl`，表格级对齐为`center`。
- 手动编号矩阵：标题段落没有有效自动编号，报告记录`numbering_mode=manual`。
- 表格负例：移除`tblPr/jc`后检查器稳定失败，错误指向“table is not centered at table level”。
- WPS实渲染：窄表格从左侧移至页面中央；自动编号模式显示“一、”“（一）”等母版编号。

## 使用边界

自动编号与手动编号是全局路线选择，不能让同一标题同时承载两套编号来源。用户提供的正式单位、学校或期刊模板优先；如果模板自身没有可用的自动编号定义，自动模式会在结构检查阶段失败并要求转专门模板处理，而不是猜测编号格式。
