## 这轮发现并修复的问题

1. 窄表格只设置了单元格文字居中，表格本体仍贴左。现在写入并检查`w:tblPr/w:jc w:val="center"`，WPS渲染确认表格位于页面中央。
2. 材料原文已有“一、”“（一）”时，自动编号模式会产生双编号。现在自动模式会去掉与模板自动编号重复的文字标记；手动模式保留原文字编号并关闭自动编号。
3. 编号选择之前没有成为统一入口的必填项。现在`pipeline.py format`缺少`--numbering-mode`会直接失败，报告记录实际选择。
4. 标题和题注的格式包缩放之前存在遗漏，当前矩阵重新验证了标题、正文、二级标题和题注的实际字号与字体。

## 视觉回归

- WPS批量渲染五种格式的陌生材料，5/5成功；五种格式均显示标题层级、居中表格和表题。
- WPS渲染自动编号模式显示模板编号；WPS渲染手动模式不显示模板自动编号。
- WPS额外渲染完整公文示例和含文本框/字段的历史校企共建方案，均成功生成页面。
- 学位论文格式在WPS中因1.5倍行距产生2页，其他同一份短样例多为1页；LibreOffice交叉渲染为1页。这是渲染器和字体环境差异，不能把一种软件的分页当成另一种软件的保证。

## 警告与边界

- 完整公文示例、MBA方案、校企共建方案和技术方案对照报告中的文本框、字段、书签等被报告为`preserve_only_warnings`，不是自动通过的视觉证明。
- 内容控件、修订、合并单元格、altChunk、嵌套表格、多节文档、宏和数字签名仍然进入专门处理分流。
- 矩阵通过证明当前覆盖样本和规则链条通过，不能替代用户提供的单位/学校/期刊正式模板，也不能承诺所有陌生Word对象都能全自动排版。
