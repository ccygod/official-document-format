# v1.2.1 第二轮审计与复杂结构分流

本次发布是在v1.2.0基础上的审计修订。重点不是增加更多格式枚举，而是让陌生文档进入入口后能更早发现“脚本不应猜测”的结构，并把可保留但不能自动证明安全的对象单独列出。

## 本次修订

- 全Story扫描正文、页眉、页脚、脚注、尾注、批注和批注扩展部件。
- 对包内XML和关系部件先做可解析性检查；发现损坏的XML时进入专门处理分流。
- 内容控件、修订、合并单元格、altChunk、嵌套表格、多节、宏和数字签名进入`requires_specialist_review`，自动流程停止写出成品。
- 文本框、字段、书签和外部关系进入`preserve_only_warnings`，自动流程不把它们误报为不可处理，但报告会要求WPS视觉复核。
- 增加“文本框是保留警告而不是阻断项”的回归测试，避免把含有常见文本框的模板一律拒绝，同时避免把它们当作已完成验收。
- 修复标题和题注没有跟随格式包字体/比例缩放的问题，并规范题注运行属性顺序，保证第二次处理不产生字节漂移。
- 继续要求`--format-profile`和`--body-half-points`显式提供；标题字号、题注和编号按格式包比例缩放。

## 验证

- Python单元测试：50项通过。
- Skill结构检查：`quick_validate.py`通过。
- CLI冒烟：格式目录和格式入口帮助均通过，五种格式包可列出。
- 真实陌生材料：保留内容、媒体、关系与二次处理幂等性检查通过；独立陌生样例的表格标题缺失会按预期失败，不会编造题注。
- WPS渲染：结构通过的输出仍需逐页验收，报告状态保持`structural_pass_visual_pending`，不会冒充视觉通过。

## 边界

这不是对所有Word对象的全自动承诺。文本框、外部关系、字体替换和复杂分页仍需目标WPS/Word打开检查；内容控件、修订、合并单元格、嵌套表格、宏、数字签名和多节复杂文档应转专门OOXML处理。
